# Psihologist-cabinet

Портал кабинетов психологов (SPA): каталог, запись, оплата/аванс, напоминания, перенос с согласием, шифрование PII.

**Репозиторий (основной):** https://github.com/A1Dmitry/Psihologist-cabinet  
Перенос в `mikhailouskayanataliya-collab/Psihologist-cabinet` отложен: целевой
репозиторий недоступен (приглашение коллаборатору не принято/нет доступа).
Инструкции сохранены в `docs/archive/repo-transfer/` — статус: открытый вопрос
к владельцу продукта. До решения текущий репозиторий — единственный источник истины.

## Запуск

```bash
python3 devserver.py 8765        # SPA-fallback: deep-link /psy/{slug} → index.html + авто-нормализация в #/psy/{slug}
# или
chmod +x serve.sh && ./serve.sh  # простой статический сервер (только корень)
```

Открыть: http://127.0.0.1:8765/

Смоук маршрутов: `python3 verify_pages.py` (или `BASE_URL=https://… python3 verify_pages.py` для Pages),
роутер Hash History: `node test_routing.mjs`, воронка записи: `node tests/booking-wizard.mjs`.

## Структура

- `index.html` — UI
- `js/models` — Code First
- `js/core/dbContext.js` — хранилище
- `js/viewmodels` — MVVM
- `js/services` — auth, crypto, vault, payment, reminders, fraud, calendar (Google), seo
- `supabase/schema.sql` — DDL БД + RLS (аноним видит только публичное; клиенты — только владельцу; запись через RPC)
- `supabase/seed.sql` — референс-данные профиля с сайта nataliamikhailouskaya.by
- `docs/DATA-MODEL.md` — модель данных сайта, сверка и маппинг в БД
- `docs/ROADMAP-OKNA.md` — роадмап: сверка функций с okna.one и бэклог задач (T-01…T-25)
- `docs/INFRA.md` — продакшен-инфраструктура: runbook Supabase/Resend/Pages, статус, чек-лист
- `docs/SCHEMA-REQUESTS.md` — очередь заявок на изменение схемы (правила для агентов 2–5)
- `docs/RULES.md` — обязательные строгие правила работы с проектом (типология «туфты», запрет самосертификации, 12-пунктовый итоговый отчёт)
- `AGENTS.md` — входная точка правил для ИИ-агентов (обязательное чтение до начала работы)
- `devserver.py` — локальный сервер со SPA-fallback (глубокие ссылки `/psy/{slug}`)
- `verify_pages.py` — смоук-проверка маршрутов (локально или GitHub Pages)

## Маршруты (индексируемые URL)

- `/` — каталог специалистов
- `/psy/{slug}` — страница специалиста: SEO-лендинг (профиль, услуги/цены, реквизиты, контакты; canonical, OG, JSON-LD schema.org)
- `/book/{slug}` — страница записи: компактный шаг выбора услуги/времени/оплаты (здесь будет развиваться сложный воронко-флоу)
- `/cabinet`, `/auth` — кабинет/вход (в sitemap/robots закрыты от индексации)
- legacy-ссылки `?book={slug}` и `/psy/{slug}#book` перенаправляют на страницу записи

## Кабинет психолога

- **Книга записей** — журнал всех записей: фильтры (предстоящие/ждут действия/прошедшие), подтверждение, перенос, заметка о сессии, неявка, «В календарь»
- **Расписание** + **Занятость** (блокировки, Google Calendar iCal)
- **Клиенты** — карточка клиента: сессии + записи о работе (журнал, виден только психологу)
- **Задачи** — дела кабинета с сроками и привязкой к клиенту
- **Блокнот** — планировщик: заметки с датой, закрепление
- **Профиль** — всё публичное содержание страницы + реквизиты (налоговые требования)

Залогиненный психолог на своей странице `/psy/{slug}` видит зелёную панель
«Это ваша публичная страница» с быстрыми переходами (Книга записей, Задачи, Блокнот, Кабинет).

## Занятость

Кабинет → «Занятость»: блокировки (выходной/занят/отпуск, весь день или интервал) закрывают слоты онлайн-записи. Google Calendar: секретный iCal-адрес импортируется в блокировки; сессии добавляются в календарь кнопкой «В календарь» (шаблонная ссылка Google, как у Calendly/Booksy).

## Данные: строго серверные

Каталог/профили/услуги/занятость загружаются только из Supabase (`loadServerCatalog`).
Если сервер недоступен или не заполнен — портал показывает причину и инструкцию
(локальный seed **не** подставляется). Демо-данные включаются только явной кнопкой
«Показать демо-данные» и помечаются жёлтой плашкой «ДЕМО».

Подключение БД: Supabase → SQL Editor → выполнить `supabase/schema.sql`, затем
`supabase/seed.sql` → в приложении нажать «Повторить» (бейдж в шапке станет
«Данные: сервер»).

## Вход психолога — одноразовый код из письма (6–8 символов)

Email → «Получить код» → **код генерируется в БД** (`auth_login_codes`, хеш SHA-256,
одноразовый, окно 2 минуты, максимум 5 попыток) и отправляется на почту специалиста
**Edge Function `auth-code`** (Resend) — в письме только код, никаких ссылок.
Психолог вводит код в поле входа → сервер проверяет код → выдаёт сессию браузера
(hashed_token → `/auth/v1/verify`), код гасится. Профиль по email привязывается к
кабинету автоматически (RPC `claim_psychologist_profile`), при регистрации — создаётся.
Пароль сейфа клиентов — опция во вкладке «Клиенты», для входа не нужен.

Настройка основного канала:
1. Применить `supabase/schema.sql` (таблица `auth_login_codes`).
2. `supabase functions deploy auth-code`
3. `supabase secrets set RESEND_API_KEY=re_...` (ключ из resend.com; для писем с
   своего домена — верифицировать домен в Resend и задать
   `MAIL_FROM="PsyПортал <код@ваш-домен>"`; без домена работает `onboarding@resend.dev`
   — только на адрес владельца аккаунта Resend).

Запасной канал (если функция ещё не задеплоена): встроенная почта Supabase Auth —
тогда в дашборде Supabase (Auth → Emails → шаблоны) в шаблонах Magic Link/OTP должен
стоять `{{ .Token }}`, иначе придёт magic-link-ссылка вместо кода.

Смоук авторизации и серверного кабинета: `node verify_auth.mjs` (26 проверок:
канал auth-code, hashed_token-сессия, честные ошибки, запасной OTP, claim/REST).

Если код не приходит или вход не проходит — на страницах «Вход» и «Каталог» есть
**«Диагностика сервера»**: она показывает по пунктам, что уже применено в вашей БД
(view, новые колонки, RPC create_booking и claim_psychologist_profile) и что нужно
выполнить в SQL Editor.

## Карточка специалиста — вся модель сайта через БД

На `/psy/{slug}` отображается полный профиль из БД: фото (по умолчанию — с сайта-
первоисточника, иначе инициалы), приветствие/подход/о себе, направления, услуги и
цены, образование, опыт, кнопки оплаты + реквизиты, **адрес практики со картой
проезда** (Google-embed + маршруты Google/Яндекс) и **контакты с мессенджерами**
(телефон, WhatsApp `wa.me`, Viber `viber://chat`, Telegram, email, соцсети) — как
принято на сайтах специалистов. Внизу — ссылка на первоисточник данных.

Смоук карточки: `node verify_profile.mjs` (29 проверок отрисовки модели сайта из
серверных строк БД).

## Онлайн-запись — 3 шага, без регистрации

`/book/{slug}`: **Услуга → Время → Контакт**.

- Индикатор прогресса; «Назад» не теряет введённые данные, «Далее» недоступна,
  пока шаг не заполнен (и понятно подписано, чего не хватает).
- **Клик по услуге — сразу её свободные окна** (с профиля: `/book/{slug}?service=<id>`).
- Сетка слотов считается по длительности услуги: 90-минутная услуга не предложит
  18:00 при приёме до 19:00 и не пересечёт чужую запись. Занятые часы зачёркнуты,
  причина — в подсказке.
- **Часовой пояс клиента**: слоты показываются и в поясе специалиста, и в вашем
  (`Intl`-определение пояса, корректный переход через DST и границы суток).
  В БД пишется время специалиста, пояс клиента — в заметке заявки (до SR-001).
- Оплата/аванс/резерв — прежняя политика кабинета; статусы звучат по-человечески
  («ждём подтверждения», «слот зарезервирован до …»).

Смоук клиентского пути: `node tests/booking-wizard.mjs` (шаги, слоты 90 мин,
часовые пояса, ссылка «услуга → окна»).

## Telegram-уведомления (свой бот психолога)

Вкладка «Уведомления» в кабинете: токен от @BotFather → «Проверить», «Найти чат»
(getUpdates), переключатели событий (новая запись / напоминания клиенту / оплаты),
«Проверить подключения (/start)». Клиент подключает напоминания по ссылке-приглашению
`https://t.me/<бот>?start=<clientId>` (карточка клиента → «Как подключить»).
Механика: напоминания и outbox новых записей уходят, пока кабинет открыт (таймер 60 с,
watermark `last_notified_session_at` от дублей); для мгновенной доставки с публичной
страницы — задать `NOTIFY_WEBHOOK_URL` в `js/services/supabaseConfig.js` и задеплоить
`supabase/functions/telegram-notify` (токен живёт только в Edge Function).
Смоук: `node verify_telegram.mjs` (57 проверок).

## Кабинет через сервер (без заглушек)

После входа все данные кабинета тянутся с сервера по RLS-владельцу и каждая мутация
сразу пишется в БД (write-through): клиенты (привязочные строки; PII — только в
шифрованном сейфе на устройстве), сессии (создание/перенос/подтверждение/неявка/оплата/удаление),
настройки (оплата, слоты, Google Calendar), блокировки занятости, услуги, задачи,
блокнот, записи о клиентах, лист ожидания. Локальное — только зеркало для рендера.

Полный исходник также в артефактах проекта (`portal/`).
