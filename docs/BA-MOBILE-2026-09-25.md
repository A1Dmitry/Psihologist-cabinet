## 0. Executive summary

Продукт — портал кабинетов психологов: публичный каталог + SEO-страница специалиста +
онлайн-запись (wizard) + кабинет психолога (журнал, расписание, клиенты, задачи, блокнот,
услуги, занятость, Telegram) + мини-кабинет клиента по секретной ссылке.

**Сильные стороны (подтверждено кодом):** серверно-авторитетная запись (`create_booking`),
duration-aware слоты с учётом пояса клиента (T-02/T-03), состояние wizard'а переживает
перерисовки (T-01), фиксация согласия (T-25), честные демо-плашки, OTP-вход с
`autocomplete="one-time-code"`, лог ошибок на сервер. Ядро домена — выше среднего по рынку.

**Главная находка №1 (мобильный приоритет): кабинет психолога с телефона функционально
неполноценен.** 5 из 15 разделов (Профиль, Ссылка записи, Оплата и защита, Напоминания,
Статистика) существуют только в десктопном сайдбаре — на мобильном недостижимы (MX-01).
Психолог со смартфона не может отредактировать публичную страницу, получить ссылку записи,
настроить оплату и напоминания. Это P0-дефект мобильного UX.

**Главная находка №2 (бизнес-логика): ключевой оффер «напоминания с подтверждением»
не замыкается в проде.** Напоминания живут только в localStorage браузера, где созданы
(`db.reminders`; таблицы reminders в `supabase/schema.sql` нет), страница ответа клиента
ищет токен в локальном хранилище (`js/app.js:1880`) → на устройстве клиента цикл не
работает; реальной доставки клиенту нет (T-15 не реализован, reminders-канала на сервере
нет). Снижение неявок — главный оффер конкурентов (окно, Планёрка, ПРАКТИКА) — сейчас
не воспроизводим продуктом (BL-01/BL-02).

Всего зафиксировано: **9 дефектов бизнес-логики (BL-01…BL-09) и 9 дефектов мобильного
UI/UX (MX-01…MX-09)**, каждый с ссылкой на код. Рекомендации — 10 функциональных
кандидатов F1…F10 (§5) с приоритетами, зависимостями и опорой на конкурентов.

> ⚠ Stop-the-Line (по `docs/CURRENT-STATE.md`): production по основному пути не работает
> (`create_booking` для anon недоступен, Edge Functions не задеплоены — #46/#35, владельцу).
> Реализация продуктовых F-задач не должна стартовать до разблокировки production
> (правило триажа: «BA-фичи #27–#31 не стартовать до #46»); сами BA-ишью оформлять можно.

## 6. Честные ограничения этого аудита

- Не проводилось юзабилити-тестирование с реальными пользователями и замеров метрик
  (конверсия воронки, неявки) — выводы UX основаны на эвристиках (touch targets,
  navigation гайдлайны) и коде, не на данных.
- Мобильный рендер проверялся статически (разметка/классы), скриншот-прогон в эмуляторе
  не выполнялся (нет браузера в песочнице) — целостность превью по RULES §5 подтверждается
  только смоук-маршрутами (`verify_pages.py`, HTTP 200).
- Конкурентные функции описаны по публичным материалам; внутренние метрики конкурентов
  неизвестны.
- Production-факты (не задеплоенные функции, недоступный `create_booking` для anon)
  взяты из `docs/CURRENT-STATE.md` (LIVE-срез 2026-09-25) и в этой сессии не перепроверялись.
