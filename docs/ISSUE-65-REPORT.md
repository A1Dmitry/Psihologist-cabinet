## 2. РЕЗУЛЬТАТ

- `js/services/calendarService.js`: `buildIcsEvent()` (VCALENDAR + VTIMEZONE + VEVENT,
  RFC 5545: CRLF, фолдинг ≤ 75 октетов UTF-8 без разрыва символов, экранирование
  TEXT), `icsFileName()`, `icsHref()` (data:text/calendar;charset=utf-8).
  Длительность считается только через `resolveDurationMinutes({durationMin, service})`.
  Конец события = момент начала + длительность, так что конец верен и через полночь,
  и через переход на летнее время. VTIMEZONE берёт смещение, действующее в момент
  встречи; если переход DST попадает внутрь встречи, добавляется второй компонент
  с точной минутой перехода.
- Страница успеха (`index.html`, `renderSuccess()` в `js/app.js`): кнопка
  «📅 Добавить в календарь (.ics)» и рядом «Google Calendar». На мобильном они
  стоят столбцом на всю ширину, на ≥sm — в строку. UID события = id записи с сервера.
- Мини-кабинет клиента (`js/views/cabinetUi.js`): «📅 В календарь» у каждой
  предстоящей встречи. Это опциональный пункт; оказался тривиальным: HTML-строка + data-URI.
- `css/tailwind.css` пересобран штатной командой из `tailwind.config.js`
  (добавлен `sm:items-center`, +65 байт). Cache-bust поднят до `?v=20260925-ics65`.
- Тесты: новый набор `tests/calendar-ics.mjs` (49 проверок) в `npm run verify`,
  две проверки мини-кабинета в `tools/verify_cabinet.mjs`.

## 4. ПОЛОЖИТЕЛЬНЫЕ РЕЗУЛЬТАТЫ

- Моменты DTSTART/DTEND в тесте восстанавливаются **независимо**, по компонентам
  VTIMEZONE из самого файла, а не через Intl генератора. Это исключает тавтологию (§1.3).
- Покрыто: полночь в поясе специалиста (23:30+60 → 00:30 следующего дня), полночь
  у клиента (Ташкент, +1 день; Нью-Йорк, −1 день), DST Берлина внутри встречи
  (90 реальных минут, DAYLIGHT в 02:00), получасовое смещение (Калькутта),
  приоритет длительности «снимок → услуга → дефолт», экранирование, UTF-8, фолдинг.
- Негативные контроли (fail-before-fix), после каждого файлы восстановлены:
  | Намеренная поломка | Результат |
  |---|---|
  | конец по настенным часам (`endOfSlot`) вместо момента | 2 FAILED (DST) |
  | фолдинг по UTF-16, а не по октетам | 1 FAILED (строки 129 октетов) |
  | своя длительность `Number(durationMin) \|\| 60` | 2 FAILED (приоритет услуги) |
  | убрана кнопка из мини-кабинета | verify_cabinet 1 FAIL + calendar-ics 1 FAILED |

## 5. ОТРИЦАТЕЛЬНЫЕ РЕЗУЛЬТАТЫ

## 7. КОРЕННЫЕ ПРИЧИНЫ

BL-08: при появлении «Добавить в календарь» был выбран единственный канал, template-link
Google, поэтому у пользователей Apple Calendar и Outlook не было способа добавить встречу
в один тап. Формат, который понимают все календари (iCalendar), в коде существовал только
в обратную сторону, для импорта занятости.

## 8. РЕМОНТ

## 9. ОСТАВШИЕСЯ РИСКИ

- iOS Safari: data-URI `text/calendar` открывает системное «Добавить в Календарь».
  Поведение зависит от версии iOS; на устройстве не проверено.
- UID для записи без серверного id (local-only режим) содержит случайную часть,
  поэтому повторное скачивание создаёт дубль события. Для server-ack записей UID стабилен.
- Найден и **не исправлен** (вне скоупа) существующий дефект первого визита
  `/book/{slug}`: оформлен как [#74](https://github.com/A1Dmitry/Psihologist-cabinet/issues/74).
