# RRSI-CACHE — кэш правильных решений и невынужденных ошибок

> Единственный канонический источник накопленного опыта исполнителей
> (правило [`docs/RULES.md`](RULES.md) §7, RRSI).
>
> **Вход в задачу (§7.1):** найти записи своего контура по тегам/«ситуации»
> и применить их наравне с правилами. **Выход из цикла:** сохранить новый урок
> по §7.3 либо явно заявить «новых уроков нет» с обоснованием.
> Повторение зафиксированной здесь ошибки — нарушение дисциплины (§7.5).
>
> Обновление записей — только по §7.3: фактический сигнал → проверка
> на исходном случае → независимый Challenger → фиксация с SHA, датой
> и маркером аудитора.

## Формат записи

```
### RRSI-NNN — <краткое имя>
- Статус: ACTIVE | CONFIRMED | СТАНДАРТИЗОВАНА | REPEALED (дата, причина)
- Контур/теги: <для поиска на входе в задачу>
- Ситуация: признак узнавания — в каких задачах/изменениях запись обязательна.
- Антипаттерн: ошибка и её корневая причина (кратко).
- Правильное решение: канонический паттерн, ссылки на код/документ.
- Доказательство: источник-сигнал, SHA, дата, АУДИТОР (по §3).
- Журнал применения: дата — задача — результат (для CONFIRMED нужно ≥ 2).
```

Статусы: **ACTIVE** — проверена на исходном случае; **CONFIRMED** — ≥ 2 успешных
применения в независимых циклах; **СТАНДАРТИЗОВАНА** — норма перенесена
в `RULES.md` / автотест / Poka-Yoke, здесь остаётся ссылка; **REPEALED** —
отменена при изменении контракта/контекста (причина и дата обязательны).

## Записи

### RRSI-001 — Канал доставки кода входа переживает перезагрузку и отказы

- **Статус:** ACTIVE (восстановлена из документированной истории репозитория
  2026-09-25; применения до восстановления в журнале не отражены).
- **Контур/теги:** `auth`, вход по одноразовому коду, `auth-code`, Edge Function,
  OTP, UI-состояние ожидания кода.
- **Ситуация:** любые изменения входа психолога (страницы «Вход», «Каталог»,
  генерация/проверка кодов, транспорт доставки, состояние ожидания кода в UI).
- **Антипаттерн:** выбранный транспорт доставки терялся при F5; при временном
  отказе Supabase Auth код сгорал, и пользователь попадал в тихий перебор
  каналов. Корневая причина: состояние канала и жизненный цикл кода
  не переживали сбой и перезагрузку.
- **Правильное решение:** транспорт и окно ввода сохраняются и восстанавливаются
  после перезагрузки; код проверяется только тем каналом, которым выслан;
  порядок на сервере — атомарный захват строки кода → создание сессии →
  гашение (`used_at`); при отказе Auth захват снимается и код можно ввести
  снова; при истёкшем окне — «Запросите новый код». См. `README.md`
  («Вход психолога», свойства из issue #14).
- **Доказательство:** источник — дефект/исправление issue #14; отчёты
  `docs/ISSUE-14-REPORT.md`, `docs/ISSUE-14-CHALLENGER.md`; контрактные тесты
  `tests/registration-flow.mjs`, `tests/auth-code-edge.mjs`,
  `tests/auth-ui-pending.mjs`. АУДИТОР: ВНЕШНИЙ — независимый челлендж-отчёт
  `docs/ISSUE-14-CHALLENGER.md` (состав записи восстановлен по документации
  репозитория, 2026-09-25, без новой независимой проверки — новый аудит
  требуется при изменении контура, §7.4 R7).
- **Журнал применения:** пусто.

### RRSI-002 — «Готово» для UI только после смоука реального сервера

- **Статус:** СТАНДАРТИЗОВАНА — норма закреплена в `RULES.md` §1 п. 5
  (форма «туфты»: поломка окружения/предпросмотра) и в преамбуле `AGENTS.md`;
  в кэше сохранена операционная механика.
- **Контур/теги:** `ui`, маршруты, страницы, предпросмотр, `devserver`,
  смоук-проверки.
- **Ситуация:** любая задача, затрагивающая страницы/маршруты/рендер
  (`index.html`, `js/views`, `js/viewmodels`, роутинг, `devserver.py`).
- **Антипаттерн:** задача объявляется решённой по зелёным юнит-проверкам в JS
  при сломанном приложении/предпросмотре; смоук прогоняется не против реального
  сервера. Корневая причина: проверяется наличие кода, а не наблюдаемое
  поведение страниц.
- **Правильное решение:** «готово» только после `python3 verify_pages.py`
  против реально поднятого `python3 devserver.py 8765` (локально) или против
  развёрнутого контура (`BASE_URL=…`); при изменении воронки записи —
  дополнительно `node tests/booking-wizard.mjs`.
- **Доказательство:** норма и механика зафиксированы в `AGENTS.md`
  («Правило целостности превью…») и `README.md` («Запуск», «Смоук маршрутов»).
  АУДИТОР: САМ — запись восстановлена из действующих документов 2026-09-25.
- **Журнал применения:** норма действует для всех задач с изменением UI.
