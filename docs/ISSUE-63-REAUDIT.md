## 7. КОРЕННЫЕ ПРИЧИНЫ (5 Why)

**D1 (панель не закрывается):**
1. Почему панель оставалась открытой? — обработчик закрывал меню только при тапе **вне** `.cab-menu`.
2. Почему так написано? — рассчитывали, что действие пункта всегда вызывает перерендер списка, который уберёт панель.
3. Почему расчёт неверен? — есть действия без перерендера: `<a href target="_blank">«В календарь»` и отмена `uiConfirm`/`uiPrompt` (`if (…await uiConfirm(…))` — ветка «отмена» не рендерит ничего).
4. Почему это не поймали тесты? — набор проверял «тап вне закрывает» и «перерендер убирает панель», но не «тап по пункту закрывает»; инвариант «меню закрыто после активации пункта» не был сформулирован.
5. Корень: **инвариант жизненного цикла всплывающего меню сформулирован по одному сценарию (тап вне) вместо полного набора сценариев закрытия** — тот же класс, что RRSI-кандидат от 2026-09-26 по #64 («UI-инвариант = состояние модели + состояние элемента управления в рендере»).

**D2 (панель под таб-баром):**
1. Почему пункты оказались недоступны? — панель рисовалась под фиксированным таб-баром и перехватывала тап.
2. Почему? — `.cab-menu { z-index: 30 }` при `.cab-tabbar { z-index: 40 }`.
3. Почему значения разошлись? — z-index таб-бара добавляли в одном файле/задаче (MX-02), z-index панели — в другом месте той же задачи, без единой шкалы слоёв.
4. Почему не поймал контроль? — проверки читали каждое правило по отдельности («панель скрыта/открывается классом», «таб-бар прижат к низу»), сравнения слоёв не было.
5. Корень: **нет канонической шкалы z-слоёв мобильного кабинета и проверки относительного порядка** (контент < таб-бар/CTA < всплывающие меню < модалки/sheet).

**D3:** комментарий писался «под защиту» без проверки факта (как генерируются id) — корень: комментарий как оправдание кода, а не как описание факта.

## 8. РЕМОНТ (системный, а не точечный)

- **D1:** закрытие меню выведено из перечисления сценариев в один инвариант:
  «любой тап, который не переключает панель и не выбирает раздел sheet,
  закрывает открытые панели». Новый сценарий закрытия не требует правки
  обработчика (DRY: одно правило вместо списка исключений).
- **D2:** шкала z-слоёв зафиксирована в комментарии правила и **закреплена
  тестом** относительного порядка: `.cab-menu > .cab-tabbar`, `.cab-menu > .book-cta`,
  `.cab-menu < 50` (модалки/sheet). Проверка читает **и исходник, и собранную
  сборку** — рассинхрон `tailwind.src.css` ↔ `tailwind.css` (когда сайт/превью
  отдаёт старую сборку) становится красным, а не тихим.
- **D3:** комментарий описывает факт (генератор id) и роль try/catch (вторая линия).
- **Poka-Yoke против ложного зелёного в новых тестах:** предусловие каждой
  поведенческой проверки входит в её условие (`openedLink === true && …`).
- **Kaizen:** урок занесён в реестр `docs/RRSI-CACHE.md` (сигнал 2026-09-26,
  #63 ре-аудит) — «инвариант всплывающего элемента = полный набор сценариев
  закрытия + относительный z-порядок против фиксированной навигации, проверенный
  и в исходнике, и в артефакте сборки».
