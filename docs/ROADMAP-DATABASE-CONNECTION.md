# Роадмап подключения правильно к Базе данных (Supabase / MCP)

Документ описывает регламент и пошаговый роадмап безопасного и корректного подключения к базе данных проекта (`phiavtroybgwyjdhqqkh`), а также взаимодействия совместимых LLM-клиентов и ИИ-агентов с базой данных и репозиторием.

---

## 1. Канонический регламент подключения

Да. Для этого есть **официальный Supabase MCP Server**: он подключает совместимый LLM-клиент к проекту, чтобы модель могла изучать схему, проверять настройки и выполнять доступные операции. Для инструкций по работе с Supabase есть также официальный плагин для AI coding agents, который объединяет MCP и Supabase Agent Skills.

**В этой сессии отдельную настройку делать не нужно:** Supabase-инструменты уже подключены к проекту `phiavtroybgwyjdhqqkh`. Я могу выполнять поддерживаемые здесь действия с Supabase, но не могу редактировать ваши локальные файлы приложения — например, `registration.js` — без подключения репозитория к среде разработки.

Если хотите подключить другой LLM-клиент, начните с официальной инструкции по Supabase MCP. Для первого знакомства используйте ограниченный доступ к одному проекту в режиме чтения:

`https://mcp.supabase.com/mcp?project_ref=phiavtroybgwyjdhqqkh&read_only=true`

Дальше клиент проведёт через вход в Supabase через браузер и авторизацию. **Не вставляйте в чат API keys, service-role key или access token.** Supabase рекомендует начинать с проекта разработки, держать подтверждение вызовов инструментов включённым и не давать агенту бесконтрольный доступ на запись к production. Для автоматического изменения файлов кода MCP сам по себе недостаточен — нужен AI-клиент, подключённый ещё и к репозиторию.

## 2. Фазы роадмапа подключения

```
[Фаза 1: Окружение и Scope]
  ├── Проект Supabase: phiavtroybgwyjdhqqkh
  └── Репозиторий: Git-окружение для изменения кода (js/, schema.sql)
           │
           ▼
[Фаза 2: MCP Интеграция (Read-Only first)]
  ├── URL: https://mcp.supabase.com/mcp?project_ref=phiavtroybgwyjdhqqkh&read_only=true
  ├── Авторизация: Browser OAuth flow
  └── Защита секретов: НИКАКИХ API/service-role ключей в чатах
           │
           ▼
[Фаза 3: Разделение полномочий (Separation of Concerns)]
  ├── MCP Server ──► Инспекция DDL, проверка RLS, аудит конфигурации
  └── Workspace  ──► Правка кода (registration.js, app.js), тесты, Git
           │
           ▼
[Фаза 4: Безопасный переход к Production]
  ├── Включение подтверждения вызовов инструментов (Tool call confirmation)
  ├── Запрет неконтролируемого доступа на запись в production-БД
  └── Применение DDL schema.sql через ревью владельцем в SQL Editor
```

### Фаза 1. Разграничение зон ответственности
1. **MCP (Model Context Protocol):**
   - Даёт модели контекст базы данных: просмотр таблиц, связей, перечислений, триггеров и RLS-политик.
   - Позволяет безопасно верифицировать соответствие реальной схемы файлу `supabase/schema.sql`.
2. **Среда разработки (Workspace / IDE / Agent Mode):**
   - Необходима для чтения и внесения изменений в файлы проекта (`js/services/registration.js`, `index.html`, `tests/` и др.).
   - Сам по себе MCP сервер не имеет доступа к локальной файловой системе проекта; для полноценной разработки требуются оба контура.

### Фаза 2. Подключение внешнего LLM-клиента
1. **Первоначальное подключение в безопасном режиме:**
   - Использовать официальный endpoint с параметром `read_only=true`:
     ```
     https://mcp.supabase.com/mcp?project_ref=phiavtroybgwyjdhqqkh&read_only=true
     ```
   - Запустить процесс авторизации через веб-интерфейс Supabase (OAuth).
2. **Инварианты безопасности (P0):**
   - Никогда не публиковать и не передавать в чат или промпты `service_role key`, `access token` или приватные ключи.
   - Держать опцию подтверждения вызовов (human-in-the-loop / confirmation prompt) включённой.
   - Тестировать любые деструктивные или изменяющие операции на тестовом/dev-проекте перед production.

### Фаза 3. Синхронизация кода и схемы
1. Изменения в структуре таблиц и функциях сначала фиксируются в `supabase/schema.sql` репозитория.
2. Проверяются контракты тестами (`tests/db-contract.mjs`, `tests/security-regression.mjs`).
3. Применение изменений к живой БД `phiavtroybgwyjdhqqkh` выполняется владельцем через Supabase SQL Editor либо через авторизованный процесс миграций с подтверждением.
