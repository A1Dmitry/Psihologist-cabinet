# Вход и регистрация через Telegram Mini App

Mini App `Specializs_bot` поддерживает вход и саморегистрацию специалиста прямо внутри Telegram. Google web-вход сохранён и помогает автоматически привязать существующий кабинет.

## Как это работает

- **Уже есть кабинет:** откройте Mini App, нажмите Google и войдите в свой прежний аккаунт. Приложение автоматически привяжет текущий Telegram к этому активному кабинету. Отдельное ручное действие в профиле — резервный вариант.
- **Кабинета ещё нет:** нажмите «Войти через Telegram». Приложение обнаружит отсутствие привязки и предложит создать новый кабинет. После подтверждения аккаунт и пустой кабинет специалиста создаются автоматически, затем откроется онбординг профиля.
- Если Telegram не привязан, сайт **не присваивает существующий кабинет по имени, username или email**. Это защищает от захвата аккаунта. При наличии старого кабинета нужно выбрать Google, а не создавать новый.

## Что проверяется на сервере

- Telegram `initData` проверяется через HMAC-SHA-256 с bot token; `auth_date` должен быть не старше 10 минут. `initDataUnsafe` из браузера не используется.
- Успешные данные входа становятся одноразовыми: digest initData сохраняется в закрытой таблице и не позволяет повторно выпустить сессию по скопированной ссылке.
- Telegram ID связывается с Supabase Auth UUID на сервере. В новом аккаунте создаётся подтверждённая техническая запись с адресом вида `telegram-<id>@telegram.invalid`; адрес не принимает почту, случайный пароль не выдаётся в браузер. Доступ возможен только через проверенный Telegram.
- Связанный существующий кабинет должен принадлежать тому же `owner_id` и быть активным. Неактивный кабинет нельзя оживить входом.
- Таблицы Telegram ID и использованных initData недоступны ролям `anon` и `authenticated`; сервисную роль использует только Edge Function.
- Bot token и service-role key не попадают в код сайта, логи и браузер.

## Одноразовая настройка владельца

Автоматизация работает после однократной настройки серверной стороны; Mini App не может безопасно сам получить секреты проекта или выполнить DDL миграцию:

1. Применить `supabase/migrations/20260926_telegram_miniapp_auth.sql` к Supabase-проекту. Для саморегистрации новых Telegram-специалистов Google provider не нужен. Для автоматической привязки уже существующего Google-кабинета Google provider и миграция `20260925_google_specialist_signup.sql` должны быть включены по их обычной процедуре.
2. В Supabase Edge Function Secrets задать `TELEGRAM_BOT_TOKEN` именно от `@Specializs_bot`. `SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY` должны быть стандартными secrets функции.
3. В BotFather проверить URL Mini App `Specialists_booking` — это должен быть опубликованный HTTPS URL приложения.
4. При merge/deploy workflow развернёт `telegram-auth`, если настроены CI secrets. Для ручного деплоя:

   ```sh
   supabase functions deploy telegram-auth --project-ref phiavtroybgwyjdhqqkh --no-verify-jwt
   ```

5. Проверка: открыть Mini App → для старого аккаунта Google-вход и автоматическая привязка; для нового Telegram — подтверждение создания кабинета, затем онбординг; закрыть/открыть Mini App и проверить повторный вход Telegram.

Без применения миграции и server secret вход останется недоступен — это сделано fail-closed, а не обходится небезопасной проверкой в браузере.

## Красная диагностическая плашка

Красный блок сверху создаёт HTML сайта (`#boot-error`) при JavaScript-ошибке или незагрузившемся скрипте; это не сообщение Telegram. Репозиторные smoke и полный тестовый гейт проверены, но фактический runtime в Telegram нужно проверить после production-деплоя. Если плашка останется, сохраните полный текст/скриншот: он содержит конкретную ошибку или URL скрипта.
